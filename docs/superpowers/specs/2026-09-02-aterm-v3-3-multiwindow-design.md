# aTerm V3.3 设计：多窗口与标签拖出

日期：2026-09-02
前置：V3.2a/b/c（设置浮层与菜单栏）已合并至 main

## 1. 目标

用户原话：「很直觉地可以把标签拖到这个窗口外面，然后外面就出现一个新的窗口，使用当前对话的」。

即：把一个终端标签拖到窗口边界之外并松手，原地弹出一个新窗口接管这个标签，
**其中正在运行的 Claude Code 会话不中断、终端历史不丢失**。

## 2. 已核实的技术前提

以下每条都实测过，不是推断：

- **拖出边界检测可行**。现有拖拽已用 `setPointerCapture`（见 `TabPanes.tsx:110` 等），
  macOS 会把 mouse-dragged 事件继续投递给最初接收 mouse-down 的窗口，因此指针移出
  窗口后 `pointermove` 仍会到达，`clientX/clientY` 为负值或超出窗口尺寸。
- **PTY 天然跨窗口可见**。`pty.rs:28` 用 `app.emit("pty-output", …)` 全应用广播，
  不是定向某个窗口。新窗口注册监听后即可收到同一个 PTY 的输出。
- **标签状态不持久化**。`store/tabs.ts` 无任何 localStorage 写入，新窗口启动是干净的
  标签集，不会与旧窗口的标签撞车。
- **滚屏可搬运**。`@xterm/addon-serialize@0.14.0` 与本仓库的 `@xterm/xterm@6.0.0`
  实测兼容：写入 `hello` + 红色 `RED` 后序列化，正文与 SGR 颜色转义均完整保留。
  该稳定版不声明 peer 依赖，与仓库既有的 addon-fit@0.11 / addon-webgl@0.19 情况一致；
  beta 线（0.15.0-beta.x）要求 `@xterm/xterm@^6.1.0-beta`，不采用。

## 3. 明确不做（本规格范围外）

- **窗格（分屏内的单个 pane）拖出成窗口**。本次只做**标签**拖出。窗格拖拽刚在 V3.1b
  大改过，再叠一层跨窗口判定，风险与收益不成比例。
- **把标签从一个窗口拖回另一个已存在的窗口**。只做「拖出成新窗口」这一个方向。
- **窗口布局的持久化与恢复**。重启应用后不恢复上次的多窗口布局。
- **多窗口下会话列表的实时同步**。各窗口的侧栏各自扫描 `~/.claude`（本就只读），
  不做跨窗口增量推送。

## 4. 交互与流程

### 4.1 拖出判定

标签拖拽过程中，`pointermove` 坐标一旦落在**当前窗口内容区之外**，进入「将拖出」状态
并给出视觉提示（形式由实现决定，但须与既有拖拽的落点提示风格一致）。

该状态下 `pointerup` 触发拖出流程；落点若回到窗口内，则完全退回既有的窗口内拖拽逻辑，
行为不变。

**边界情况**：若被拖的标签是该窗口内**唯一**的标签，拖出等价于「把窗口整体搬到新窗口」，
没有意义——此时**不触发拖出**，退回既有行为。

### 4.2 新窗口创建与交接

必须保证：**新窗口确认接管之后，旧窗口才移除自己的标签**。顺序反了会在新窗口创建
失败时丢掉用户的会话。

1. 旧窗口序列化该标签终端的缓冲（`SerializeAddon.serialize()`）。
2. 旧窗口调用 Rust 命令创建新窗口，传入屏幕坐标（取 `pointerup` 落点），命令返回新窗口 label。
3. 新窗口启动，前端就绪后 emit 就绪事件，带自己的 label。
4. 旧窗口收到就绪事件，用 `emitTo(label, …)` 把接管载荷定向发给新窗口：
   `ptyId`、`sessionId`、标题、cwd、序列化滚屏、终端尺寸。
5. 新窗口据此建标签与窗格，把滚屏写入终端，`attachPty(ptyId, …)` 接上实时输出，
   然后 `emitTo` 回一个接管确认。
6. 旧窗口收到确认后，**移除该标签但不 kill PTY**。

**为何不用 URL 查询参数传载荷**：序列化滚屏可达数十 KB，超出 URL 长度的合理范围。

**输出不会丢**：`pty-output` 是广播，新窗口的 `ptyBuffer` 从其监听注册那一刻起即开始
缓存，`attachPty` 时回放（见 `ptyBuffer.ts:27-36` 的既有实现）。交接期间两个窗口都能
收到输出，不存在空档。

### 4.3 超时与失败

第 3、5 步都要有超时。任一步失败或超时：旧窗口**保留标签不动**，关掉已创建的新窗口，
并给出可见错误提示。**绝不允许出现「两个窗口都没有这个标签」的状态。**

## 5. 必须修正的既有单窗口假设

以下每条都是当前代码里写死的单窗口前提，多窗口后会出错。

### 5.1 【最高优先级】ACL capability 的窗口作用域

`src-tauri/capabilities/default.json` 现为：

```json
"windows": ["main"]
```

新窗口 label 不是 `main`，因此它**一个权限都拿不到**，其发出的每个 `invoke()` 都会失败。

**这正是本项目栽过的那类问题**：`core:window:allow-set-size` 未授权曾导致面板窗口联动
在打包版里完全失效，而当时 748 个测试全绿。**单元测试对此毫无信号，必须真机验收。**

新窗口 label 约定 `term-<uuid>`；capability 的 `windows` 相应改为 `["main", "term-*"]`。

### 5.2 关闭确认要跨窗口统计

`src/closeRequest.ts` 的 `countLiveTerminalTabs()` 数的是**本窗口**的标签。⌘Q 是应用级
退出，必须统计**所有窗口**的存活会话，否则漏报。

方案：新增 Rust 命令返回当前存活 PTY 总数（`PtyManager` 本就掌握全部），前端改用它，
不再自己遍历本窗口标签。

### 5.3 窗口关闭只杀自己的 PTY

`lib.rs:438` 硬编码 `if window.label() != "main" { return }`。多窗口后每个窗口的
`CloseRequested` 都要处理，且关闭一个窗口只应终止**它自己持有的**那些 PTY，不得误伤
其它窗口。

### 5.4 菜单事件要定向到聚焦窗口

`emit_open_settings` 与 `menu-theme-mode` 现在是 `app.emit` 广播。多窗口下点一次
「设置…」会在**所有**窗口同时弹出浮层。应改为 `emit_to` 当前聚焦的窗口。

### 5.5 主题切换要跨窗口同步

主题状态在各窗口自己的 zustand 里，CSS 变量写在各自 document 上。在一个窗口改主题，
其它窗口不会更新（localStorage 虽共享，但只在启动时读）。需广播主题变更事件，其它
窗口收到后重新应用。

## 6. 全局约束

- **本仓库没有 jest-dom**。禁 `toBeInTheDocument` / `toHaveClass` / `toHaveValue` /
  `toHaveTextContent`，只用 vitest 内置断言。
- **所有颜色取自主题 CSS 变量**，禁硬编码 hex/rgb/hsl/颜色名（28 主题 × 3 模式）。
- **受保护文件**：`src/components/ConversationPanel.tsx`、`src/components/TerminalView.tsx`。
  本规格**很可能需要改动 TerminalView**（序列化滚屏、接管 PTY）——每次改动单独申请
  批准，改动面严格限制在申请范围内。
- **localStorage 键名不得变更**；别名 key 格式 `${dirName}::${rootKey}`（双冒号）不得变更。
- **aTerm 对 `~/.claude` 只读**，唯一例外是 hooks 安装器（用户明确点击时）。
- **测试绝不允许碰真实 `~/.claude`**。
- 新增依赖仅限 `@xterm/addon-serialize@0.14.0`（已实测兼容），不得再加别的。
- 基线：`npx vitest run` 881 通过 / 64 文件；`cargo test` 127 通过；`npm run build` 干净。

## 7. 测试要求

前端：拖出判定的边界（窗口内/外、唯一标签不触发）；交接握手每一步及其超时分支；
序列化载荷的往返；**接管失败时标签必须留在原窗口**。

Rust：新窗口创建命令的参数校验与失败降级；存活 PTY 计数；关窗只杀自己的 PTY。

**跨窗口的真实行为单元测试覆盖不到**，以下必须真机验收：

1. 新窗口里的 `invoke` 真的能用（ACL 作用域，见 §5.1）
2. 拖出后原会话继续运行、终端历史完整
3. ⌘Q 在多窗口下的确认框计数正确
4. 关掉一个窗口不影响其它窗口的会话
5. 点「设置…」只在当前窗口弹出
6. 在一个窗口改主题，其它窗口同步

## 8. 风险

| 风险 | 应对 |
|---|---|
| 新窗口无权限（ACL 作用域） | §5.1；必须真机验收，单测无信号 |
| 交接失败导致标签丢失 | §4.3：先确认后移除 + 超时回滚，绝不允许两边都没有 |
| 拖出判定误伤既有窗口内拖拽 | 落点回到窗口内时完全退回既有逻辑，保留全部既有测试 |
| 改动受保护文件 TerminalView | 每次单独申请批准，限定改动面 |
| 关窗误杀其它窗口的 PTY | §5.3 + 真机验收第 4 条 |
