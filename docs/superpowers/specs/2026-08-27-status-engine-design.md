# 状态引擎设计文档（P2 子项 B）

日期：2026-08-27
状态：草案，待用户确认
前置：P1 会话索引（`sessions/parser.rs`、`scan.rs`）、P2a 对话解析与增量缓存（`sessions/conversation.rs`）

## 1. 目标

让 aTerm 实时知道**每个会话此刻在干什么**，为 P2c 总览方块页提供状态源，并在此之前先把状态呈现到主页卡片与侧边栏。

三种状态（沿用总设计 §4）：

| 状态 | 含义 | 呈现 |
|---|---|---|
| **运行中** | Claude 正在工作 | 蓝色 + 转圈 |
| **等你回答** | 停下来在等用户输入/授权 | 橙色 |
| **已完成** | 本轮结束或进程已退出 | 绿色 / 灰色 |

**非目标**
- 不做总览方块页本身（P2c）
- 不做跨机器/远程会话
- 不改变任何已有的终端、面板、分屏行为

## 2. 关键设计变更：hooks 不再走 localhost 端口

**原设计**（总设计 §7）让 hook 命令向 aTerm 的本地端口发一次 POST。**本文档改为：hook 命令向一个约定文件追加一行**，由已有的文件监听器一并捕获。

理由：
- **无需监听网络端口** —— 省掉端口分配与冲突处理，也不会触发 macOS 的网络权限询问
- **无攻击面** —— 不存在本机任意进程都能 POST 进来的入口
- **实现更小** —— 复用同一套文件监听，不引入 HTTP 服务端依赖
- **延迟可忽略** —— 追加 + FSEvents 是毫秒级，远低于人眼阈值

代价：事件文件需要按大小轮转，避免无限增长（见 §5）。

## 3. 架构

```
~/.claude/projects/**/*.jsonl ─┐
                               ├─→ 文件监听（notify/FSEvents，递归）
~/Library/Application Support/aTerm/hook-events.jsonl ─┘
                               │
                               ├─→ 事件去抖（每文件 120ms 合并）
                               ├─→ 增量元数据解析（仅读尾部，复用既有有界读取）
                               ├─→ 进程存活探测（按需，不轮询）
                               │
                               └─→ 状态引擎 ──→ Tauri 事件 `session-status`
                                                 → 前端 store → 主页卡片 / 侧边栏
```

新增 Rust 模块：`src-tauri/src/status/mod.rs`、`watcher.rs`、`engine.rs`、`hooks.rs`。

新增依赖：`notify`（跨平台文件监听，macOS 走 FSEvents）。

## 4. 状态判定

按优先级从高到低，**先命中先定**：

1. 该会话最近一条 hook 事件是 `Notification` 且晚于最后一次 jsonl 追加 → **等你回答**
2. 该会话最近一条 hook 事件是 `Stop` 且晚于最后一次 jsonl 追加 → **已完成**
3. jsonl 在最近 `ACTIVE_WINDOW`（默认 5 秒）内有追加 → **运行中**
4. 该会话有存活进程但超过 `ACTIVE_WINDOW` 无追加 → **等你回答**（启发式回退）
5. 无存活进程 → **已完成**

**未安装 hooks 时**只用 3/4/5，「等你回答」靠启发式，可能慢几秒或偶有误判——这是可接受的降级，与总设计 §7 一致。

**进程存活探测**：不轮询。仅在规则 4/5 需要区分时，读取 `~/.claude/sessions/*.json`（Claude Code 自己维护的会话登记表，含 pid 与 status）并校验 pid 是否存活。该目录同样纳入监听。

## 5. hook 事件文件

- 路径：`~/Library/Application Support/aTerm/hook-events.jsonl`（aTerm 自有数据目录，**不写入 `~/.claude/` 之外的任何位置**）
- 每行：`{"event":"Notification"|"Stop","sessionId":"...","ts":<毫秒>}`
- 安装到 `~/.claude/settings.json` 的 hook 命令是一条极小的 shell：向该文件追加一行 JSON，不依赖 aTerm 是否在运行
- **轮转**：文件超过 1 MB 时截断保留尾部 200 行。状态判定只关心「每个会话的最后一条事件」，历史无价值

## 6. hooks 安装器

- **绝不自动写入。** 首次检测到未安装时，在主页顶部显示一条可关闭的提示条，说明「安装后『等你回答』状态才精准」，并提供「安装」按钮；用户点击才写
- 写入前**备份** `~/.claude/settings.json` 到 aTerm 自有目录，附时间戳
- **幂等**：已存在同名 hook 则更新而不重复追加；提供「卸载」按钮完整移除
- 只添加 `Notification` 与 `Stop` 两个 hook，不触碰用户已有的任何其他配置项
- 解析失败或结构异常时**放弃写入并提示**，绝不覆盖用户配置

## 7. 前端

- 新 store `src/store/status.ts`：`Map<threadKey, SessionStatus>`，订阅 Tauri 的 `session-status` 事件
- **主页卡片**：项目卡片显示聚合状态点（有任一运行中→蓝；有等待→橙；否则绿），展开的会话行显示各自状态
- **侧边栏**：每条会话前显示状态点
- 状态色沿用主题派生变量体系，不新增硬编码颜色
- 转圈动画仅在「运行中」出现，且**面板/页面不可见时不渲染动画**（避免无谓重绘）

## 8. 性能与资源

- 监听递归覆盖 `~/.claude/projects`，但**只读尾部元数据**（复用 `read_tail_lines`，64KB 上限），不做全量解析
- 每文件 120ms 去抖：Claude 高频输出时不会引发解析风暴
- 状态变化才发事件；无变化不推送
- 目标：单会话高频输出时，状态引擎 CPU 占用可忽略（验收时实测并记录）

## 9. 测试策略

**Rust**
- 状态判定纯函数：五条规则各一例 + 优先级冲突（hook 事件早于/晚于最后追加）
- hook 事件文件解析：畸形行跳过、轮转后仍取到最后事件
- hooks 安装器：全新安装、已存在时幂等更新、卸载、settings.json 畸形时拒绝写入且不损坏原文件（用临时目录，**绝不碰真实 `~/.claude`**）
- 去抖：连续事件合并为一次解析

**前端**
- store 按事件更新对应会话状态
- 主页卡片聚合规则（多会话不同状态 → 卡片显示哪个）
- 未安装 hooks 时提示条出现，安装后消失

**手动验收**
- 真机跑一个 claude 会话，观察三种状态是否如实变化
- 安装 hooks 后「等你回答」是否明显更快更准
- 高频输出时 CPU 占用

## 10. 风险

| 风险 | 对策 |
|---|---|
| 写坏用户的 `~/.claude/settings.json` | 写前备份、幂等、结构异常即放弃、提供卸载；测试只用临时目录 |
| 监听大量文件导致资源占用 | 递归监听但只读尾部；去抖；只在状态变化时推送 |
| 启发式误判「等你回答」 | 明确标注为降级路径；装了 hooks 即精准；不因误判做任何破坏性动作 |
| `~/.claude/sessions/` 是 Claude Code 内部格式，可能变 | 仅作为进程存活的辅助信号；读取失败时退回「有追加即运行中」 |
