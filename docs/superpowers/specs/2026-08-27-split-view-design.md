# 标签内分屏（Split View）设计文档

日期：2026-08-27
状态：已与项目所有者确认（分屏单位、创建方式、布局与拖拽、焦点与快捷键）
所属：P2 子项 D（在 A 对话面板之后、B 状态引擎之前插入）

## 1. 目标

在**一个标签内**并排显示 2–3 个对话，供大屏下同时盯多个会话。

- 每个窗格清楚标注它是哪个对话
- 默认等分（2 个各占一半，3 个各占三分之一），分隔条可拖拽调宽
- 键盘和鼠标都能创建与切换

**非目标（第一版）**
- 不做上下分屏（只做左右列）
- 不做超过 3 个窗格
- 不做跨标签拖拽窗格
- 不做退出后恢复分屏布局（当前版本本就不恢复标签）

## 2. 数据模型变更

当前 `Tab` 直接持有一个终端（`ptyId` 等）。改为：

```ts
type Pane = {
  id: string
  ptyId: string
  title: string           // 窗格标题栏显示
  threadKey?: string      // 会话去重键
  dirName?: string        // 供对话面板使用
  rootKey?: string
}
type Tab = {
  id: string
  kind: 'home' | 'term'
  title: string           // 标签标题：单窗格时等于该窗格标题；多窗格时为「N 个对话」或用户重命名
  panes: Pane[]           // home 标签为空数组
  activePaneId?: string
  paneWidths?: number[]   // 各窗格宽度占比，和为 1；不存在时按等分
}
```

**迁移要点**：`useTabs` 现有的 `openTerminal` / `closeTab` / `focusThread` 语义要沿用到窗格层：
- `focusThread(threadKey)` 需在**所有标签的所有窗格**中查找；命中后既切到该标签，也把该窗格设为激活窗格
- `closeTab` 关闭标签时须逐个终止其全部窗格的 PTY（沿用既有的"仍在运行则确认"逻辑，一次确认覆盖整个标签，提示中说明会终止几个会话）

## 3. 布局与拖拽

- 一个标签的内容区横向排列其 `panes`，默认等分（N 个窗格各 1/N）
- 相邻窗格之间有可拖拽的竖直分隔条（`cursor: col-resize`），拖动改变两侧占比，其余窗格不受影响
- **每个窗格最小宽度 320px**；拖到极限即停，不允许把窗格挤没
- 双击分隔条恢复等分
- 占比存于 `Tab.paneWidths`（内存态，不持久化——与"不恢复布局"的非目标一致）
- 窗口尺寸变化时按占比重算像素宽度；每个窗格的终端各自沿用既有的 ResizeObserver + rAF 重排路径（**不得修改 `TerminalView.tsx` 内部**）

## 4. 窗格标题栏

每个窗格顶部一条细标题栏（约 24px）：

- 左侧：该窗格的对话标题（过长截断）
- 右侧：关闭窗格的 `×`（该窗格 PTY 仍在运行时弹确认，沿用既有机制）
- 聚焦窗格的标题栏与边框用强调色标出（使用既有 CSS 变量，不新增调色板条目）
- 单窗格时**不显示**标题栏（避免占用高度并与现状保持一致）

## 5. 创建分屏

两条路径都要（用户明确要求）：

**A. 快捷键 / 菜单**
- `⌘D` 在当前标签内向右新建一个窗格
- 新窗格先显示一个**会话选择列表**（复用主页的项目/会话数据源）：可选「新终端（zsh）」、「新对话」、或任一历史会话
- 选定后该窗格启动对应终端；未选定前窗格显示该列表，不占用 PTY

**B. 从侧边栏拖入**
- 把侧边栏「最近会话」中的一条拖到某个标签内容区，落点在**右半侧**则在右侧新建窗格，**左半侧**则在左侧新建
- 拖拽过程中显示落点指示（半透明色块，使用既有变量）
- 已达 3 个窗格时拒绝并给出轻提示

**C. 拖出去 / 右键菜单（用户明确要求，A/B 的反方向）**

A/B 两条路径都只能把窗格"拖进来"，用户反馈这是主要痛点——分屏后没有回头路。反方向
同样给两条：

- **拖出去**：多窗格标签的窗格标题栏（§4，仅多窗格时渲染）本身就是拖拽手柄。把它
  拖出所在标签的窗格行——松手时落在标签栏上，按落点位置插入；落在窗格行范围之外
  的任何其它地方，追加到标签栏末尾——该窗格独立成一个新标签，新标签成为激活标签，
  该窗格是其焦点。松手时若光标仍停留在源标签自己的窗格行范围内，视为没有真的拖
  出去，不产生任何变化（不支持"在同一行内拖拽重新排序"）。
- **右键菜单**：右键窗格标题栏弹出一个自包含的小菜单（无需引入菜单库），两项：
  「移出为独立标签」（等同拖出去，只是没有落点、固定追加到末尾）、「关闭窗格」
  （直接复用 §4 已有的关闭确认逻辑，不是新流程）。点菜单外部/`Escape`/窗口失焦
  均可关闭菜单。
- 源标签只剩这一个窗格时，"移出为独立标签"是空操作——它已经是独立标签，没有
  什么可拆的。
- **不变量（与场景 A/B 共享，且同样关键）**：无论哪个方向，被移动的窗格对象——
  含其 `id`/`ptyId`——必须原样保留，绝不重新创建。`TerminalLayer.tsx` 按 `pane.id`
  做 key，只要 id 不变就不会卸载重挂对应的 `<TerminalView>`；一旦意外重新创建
  pane 对象（哪怕内容完全相同），xterm 实例与其内部回滚缓冲都会被销毁重建，用户
  刚刚跑出来的输出、滚动位置全部丢失。这条不变量在自动化测试里以"移动前后 DOM
  节点是同一个引用、mount effect 只跑一次"的形式断言（`TerminalLayer.test.tsx`）。

## 6. 焦点与快捷键

- 点击窗格内任意位置即聚焦该窗格；键盘输入进入聚焦窗格
- `⌘⌥←` / `⌘⌥→` 在窗格间移动焦点（不跨标签，边界不循环）
- `Ctrl+Tab` / `Ctrl+Shift+Tab` **语义不变**，仍在标签间循环
- `⌘W` 关闭**当前窗格**；当标签只剩一个窗格时等同于关闭标签（沿用既有确认逻辑）
- 快捷键统一在 `App.tsx` 既有的捕获阶段 keydown 监听里处理，不新增监听器

## 7. 与对话面板的关系

- 右侧对话面板始终跟随**聚焦窗格**所属的会话；切换聚焦窗格即切换面板内容
- 切换时必须走既有的 `requestIdRef` 过期响应保护（**不得绕过或削弱**）
- 面板收起时不加载（既有行为保持）

## 8. 窄窗口下的降级

窗口宽度不足以让所有窗格达到 320px 最小宽度时：

- 优先收起右侧对话面板（若展开）
- 仍不足则**拒绝新建窗格**并提示，而不是把已有窗格压到不可用

## 9. 测试策略

**前端（无法用 jsdom 验证真实布局，因此重点测状态机与纯函数）**
- 窗格增删：新建至 3 个后拒绝第 4 个；关闭窗格后占比重新分配；关闭最后一个窗格等同关闭标签
- `focusThread` 跨标签跨窗格查找命中后同时切标签与切窗格
- 等分与拖拽占比计算的纯函数：两窗格、三窗格、拖到最小宽度边界后夹紧
- `⌘⌥←/→` 焦点移动在边界不循环；`Ctrl+Tab` 仍切标签不切窗格
- `⌘W` 在多窗格与单窗格下的分支
- 对话面板跟随聚焦窗格切换内容
- 窗格拖出/右键菜单拆分为独立标签（§5-C）：插入位置（追加末尾 vs 落在标签栏具体
  位置）、源标签只剩一个窗格时的空操作，以及移动前后 DOM 节点身份不变（同场景 A/B
  那套"mount 只跑一次"断言，见 `TerminalLayer.test.tsx`）
- 拖拽期间的文本选择屏蔽与跟随光标指示（§5-C 之后新增的交互打磨）：body class 在
  拖拽开始时加上、在松手与 `pointercancel` 两条退出路径都会被移除；指示显示正在
  拖拽对象的标题；4px 阈值内的普通点击既不设置 class 也不显示指示

**手动验收（自动化测不到）**
- 拖拽分隔条时两侧终端是否实时正确重排
- 拖放创建窗格的落点指示是否符合直觉
- 三窗格在实际大屏下的可读性
- 拖拽手感与跟随光标指示是否顺畅自然（跟手、无明显延迟或跳变）；把窗格拖出后
  scrollback/滚动位置是否与移动前完全一致；右键菜单在贴近屏幕边缘时的定位是否
  被正确钳制在可视区内

## 10. 风险

| 风险 | 对策 |
|---|---|
| `Tab` 结构变更牵动 tabs store、App、TabBar、actions、对话面板等多处，回归面大 | 分两步实施：先做「Tab 持有 panes 数组但只允许 1 个」的等价重构并保证既有测试全绿，再加多窗格能力 |
| 多个 xterm 实例同时存在，资源占用上升 | 上限 3 个窗格；WebGL 渲染器本就每实例独立，实测再评估 |
| 分隔条拖拽与终端自身的选择/滚动冲突 | 分隔条为独立元素并使用 pointer capture，不覆盖终端区域 |
| 既有的受保护逻辑（ResizeObserver/rAF、wheel 放大、主题订阅、requestIdRef）被牵连改动 | 实施时列为受保护区，逐条核对字节未变 |
| 拖拽标签/窗格标题栏/侧边栏会话时，浏览器默认行为会顺带选中沿途文字；拖拽过程中又没有任何视觉反馈，不像在"拖"东西 | 拖拽开始时给 `document.body` 加 `user-select:none` 的 class、结束时无条件移除（覆盖松手与 `pointercancel` 两条退出路径，任何提前 `return` 都不会让它卡住）；同时显示一个跟随光标、半透明的拖拽指示（`store/dragGhost.ts`，三处拖拽源共用同一份状态机） |
| §5-C"拖出去"与§5-B"拖进来"共享同一条 pane-id/ptyId 保留不变量，日后改动若不慎打破它会静默丢失用户的 scrollback | 两个方向都有独立的 DOM 节点身份测试兜底（`TerminalLayer.test.tsx`：移动前后同一个 `<TerminalView>` 实例、mount effect 只跑一次），一旦被打破会被测试立刻抓到，不依赖人工肉眼核对 |
