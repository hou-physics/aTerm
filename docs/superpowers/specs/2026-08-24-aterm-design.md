# aTerm 设计文档

日期：2026-08-24
状态：已与项目所有者逐节确认（主页布局、总览页、方块规格、结构图、状态检测机制、P5 预留均经可视化确认）

## 1. 概述

aTerm 是一个 macOS 桌面终端，专为 Claude Code 的 agent 工作流设计。它首先是一个真正的终端（真实 zsh 登录 shell），在此之上提供：以项目为中心的会话浏览与一键恢复、多对话实时状态监管（总览方块页）、sub-agent 结构可视化，以及后期的可视化 agent 流水线编排。

**目标**
- 完全替代现有终端完成日常 Claude Code 工作
- 同时监管多个对话的实时状态（运行中 / 等待回答 / 已完成）
- 一键恢复任何历史对话
- 后期：像搭积木一样编排多 agent 自动化流水线

**非目标**
- 不支持 Claude Code 以外的 agent CLI（不做通用适配）
- 不做跨平台（仅 macOS）
- 不做协作/分发/收费功能（个人工具）

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 应用外壳 | Tauri 2（Rust） | 内存占用远低于 Electron；系统 WebView |
| 前端 | React + TypeScript + Vite | 拖拽、状态色、DAG 图等复杂 UI 迭代快 |
| 终端渲染 | xterm.js | VS Code 同款，IME/中文输入成熟 |
| PTY | portable-pty（Rust） | 每个终端标签一个真实 shell |
| 文件监听 | notify（FSEvents 后端） | 监听 ~/.claude/projects 增量变化 |
| aTerm 自有数据 | JSON 文件，存于 ~/Library/Application Support/aTerm/ | 重命名、方块位置、固定标签、设置、（P5）pipelines/ |

## 3. 架构

三层结构：

```
[数据来源]                      [Rust 核心 (Tauri 2)]              [React 界面]
~/.claude/projects/**/*.jsonl → 会话索引器（扫描+增量解析）      → 主页（启动器式）
Claude Code hooks 事件        → 状态引擎（蓝/橙/绿，内部事件总线）→ 项目总览页（方块网格+拖拽）
zsh / claude CLI              → 统一启动入口（任务描述→跑claude） → 终端标签（xterm.js）
                                hooks 接收端（localhost 小端口）  → DAG 图渲染器（P4 只读，P5 可编辑）
                                                                   右下状态栏（模型/强度/权限）
```

**硬性原则**
- 对 `~/.claude/` 只读；唯一例外是经用户同意安装的两条 hook（写入 `~/.claude/settings.json`）
- aTerm 崩溃不影响任何 Claude 会话：claude 进程由系统管理，记录文件由 Claude Code 自己写
- aTerm 自有数据与 Claude 数据完全分离，按会话链 id 关联

## 4. 数据模型

- **项目（Project）** = `~/.claude/projects/` 下的一个目录，对应磁盘上的真实文件夹
- **会话（Session）** = 一个 jsonl 记录文件
- **会话链（Thread）** = 若干会话文件串成的一个逻辑对话。Claude Code 恢复会话时会生成新文件延续旧对话；aTerm 的判定规则：**两个文件的首条用户消息 uuid 相同即为同链**（恢复产生的新文件会复制旧消息及其 uuid，因此首条用户消息 uuid 保持不变；受"只读文件头部"约束，不做全量 uuid 交集比对——已知局限：某些压缩/裁剪形态可能令链在极端情况下断开），链首为最早的文件。**方块 = 会话链**，重命名与位置跟随链。
- **活动终端（LiveTerminal）** = 一个 PTY；运行 `claude --resume` 时"附着"到对应会话链
- **方块元数据** = 自定义名称、网格位置、是否固定为标签、归档标记（存 aTerm 自有数据，键为链 id）

**状态机（方块颜色）**，判定优先级从高到低：

1. hooks `Notification` → **橙**（等你回答，脉冲动画）
2. hooks `Stop` → **绿**（本轮完成）
3. jsonl 正在追加 → **蓝**（运行中，转圈）
4. claude 进程退出 / 无活动 → 定格为完成态（绿/灰）

无 hooks 时降级启发式：文件停止追加 + 进程存活 + 最后记录为提问/权限请求 → 橙。

## 5. 界面设计（已经可视化确认）

### 5.1 主页（启动器式，方案 A）
- 中部：命令输入框（回车即在新标签页执行；支持 ⌘K 聚焦）
- 下方：最近项目卡片网格（文件夹名 + 会话数 + 聚合状态点），点击进入项目总览页
- 左侧：常驻可折叠侧边栏——最近会话列表（带状态点），点击直接恢复；下方列其他项目
- 另有「打开文件夹」入口，把任意目录变成项目

### 5.2 项目总览页
- 标签条：`⌂ 主页`、`▦ <项目名>·总览`（常驻）、被固定的会话标签（浏览器式平行排布）、`＋`
- 方块网格：默认每行多个；**打开时按最后活动时间排序（新→旧）**；打开期间不自动重排；可自由拖拽排布（位置持久化）
- 右键菜单：打开 / 在新窗口打开 / 固定为标签页 / 重命名 / 归档
- 底部状态栏（常驻）：内容随当前标签变化——会话标签显示**该会话的模型 · effort 强度 · 权限模式**；总览/主页标签显示会话统计（n 个会话 · n 运行中 · n 等待回答）+ 全局默认模型

### 5.3 方块规格（标准档 + 上下文徽章）
- 标题（默认取首条用户消息摘要，可重命名）
- 状态标识：蓝色转圈（运行中）/ 橙色脉冲点（等你回答）/ 绿色点（完成）；整块底色与边框随状态着色（蓝/橙/绿浅色系）
- 小字一行：抓取的「正在干什么 / 问了什么」预览
- 徽章仅四枚：模型、sub-agent 数（⑂ n，有才显示）、相对时间、上下文用量（如 `上下文 45%` = 最近一条 assistant 消息的 usage token 合计 ÷ 该模型上下文窗口大小）

### 5.4 会话页（终端标签）
- 就是一个 xterm.js 终端，内跑交互式 claude（Claude Code 自带 TUI 完整保留）
- （P4）顶部可展开折叠面板显示本会话 sub-agent 结构图

## 6. 关键流程

1. **发现**：启动时扫描 `~/.claude/projects/`；每个 jsonl 只读头部（标题）与尾部（近况、模型、上下文）——**永不全量解析**（已存在 5.8MB 单文件）；索引缓存（记录文件大小/mtime/解析偏移），重启秒开、增量更新。
2. **实时刷新**：FSEvents 监听 → jsonl 追加时仅解析新增字节 → 更新预览/上下文/⑂ 数 → Tauri 事件推给前端 → 方块原地更新（不重排）。hooks 事件即时改色。
3. **恢复**：点方块/侧边栏 → 新标签 → 项目目录内 `claude --resume <会话id>`；新产生的延续文件按会话链规则并入原方块。
4. **新建**：总览页「＋新对话」→ 新标签跑 `claude`；监听器发现新文件后方块自动出现。主页输入框可跑任意命令。
5. **关闭标签**：运行中弹确认（终止本次运行，方块定格；历史不丢，可随时恢复）。「后台继续跑」列为后期增强。

## 7. 状态检测机制（已确认方案）

**文件监听打底 + hooks 增强**：
- 打底：jsonl 监听 + 进程存活检查，覆盖任何来源启动的会话（包括其他终端里启动的）
- 增强：首次启动征求同意，一键向 `~/.claude/settings.json` 注册 `Notification` 与 `Stop` 两条 hook（命令为向 aTerm 的 localhost 端口发一次 POST，毫秒级）；未安装/被删除时自动降级为启发式
- hooks 安装器具备：检测已存在配置、幂等安装、一键卸载

## 8. Sub-agent 结构图（P4）

- 数据来源：会话记录中的 `isSidechain`、`parentUuid`、Task 工具调用及时间戳 → 自动重建 DAG（时间区间重叠 = 平行分叉；先后衔接 = 顺序链；结果虚线返回主 agent）
- 节点信息：agent 类型/任务名 + 状态（完成/运行中/排队）+ 一行小字（在干什么/耗时）
- 入口（两处，已确认）：① 总览页点方块 ⑂ 徽章 → 背景压暗、该块放大居中、下方展开结构图，Esc 收回；② 会话页顶部折叠面板
- 历史（已完成）会话同样可回看结构图
- **实现约束：图模型必须是通用 DAG（节点+有向边+状态），渲染器只读/可编辑两种模式——P5 直接复用**

## 9. P5：可视化 Pipeline 编排（正式需求，非后门）

**目标**：在编辑器里拖节点、连箭头，搭建多 agent 自动化流水线，运行时无需人工参与，跑完通知。

**节点 = 一次 claude 运行**（无头模式 `claude -p` 捕获产物，或 `--resume` 带记忆返场）。点开节点可配置：

1. **角色提示词**：用户写死的本地 prompt（如 写作者/审计/核验/裁决），可存入**项目角色模板库**复用
2. **记忆模式**：空白（无记忆上场）/ 延续自己上次的记忆（resume，实现回环核验）/ 接续指定会话
3. **输入映射**：仅接收连线上标注的上游产物（整体或切段，如"仅第 3 段"）
4. **项目读取范围**：可读整个项目 / 仅指定路径 / 仅交接物（对应 claude 的目录与权限控制）

**信息屏障是硬的**：aTerm 只把连线指定的产物注入节点提示词，节点物理上接触不到其他信息（区别于对话内 sub-agent 的"软"屏障——后者靠主 agent 自觉）。

**边界说明**：对话内部自带的 sub-agent（⑂）由主 agent 自行调度，外部不可改接线；P5 编排的是 aTerm 启动的独立会话。两者共用同一套 DAG 视觉语言。每个角色会话在总览页显示为方块，状态色一致。

**为 P5 预留的三条地基（P1 起生效的架构纪律，不提前写多余代码）**
1. DAG 图模型通用化（P4 与 P5 共用）
2. 统一启动入口：一份任务描述（交互/无头、提示词、resume 目标、模型、cwd、权限）→ 跑 claude
3. 数据目录预留 `pipelines/`

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| jsonl 为 Claude Code 内部格式，可能随版本变化 | 解析集中单模块；防御性解析（缺字段降级显示，最坏方块只剩标题+时间）；真实样本 fixture 测试锁行为；终端功能永不受影响 |
| hooks 未装/被删 | 自动降级启发式；hooks 仅是增强非单点 |
| 「等你回答」误判（无 hooks 时） | 启发式三条件；有 hooks 以 hooks 为准 |
| 大文件/大量会话性能 | 增量解析 + 偏移缓存 + 必要时列表虚拟化 |
| 中文输入法 | xterm.js IME 成熟；验收清单专项测试 |
| claude 未安装/过老 | 主页提示；终端功能照常 |

## 11. 测试策略

- **Rust 核心（TDD）**：jsonl 解析器用脱敏真实样本做 fixture；状态机全转换路径；会话链识别；hooks 接收端
- **前端**：组件测试（各状态方块渲染、时间排序、拖拽位置持久化、重命名）
- **端到端**：每期结束以真实 `~/.claude` 数据 + 真实 claude 会话做手动验收（含中文输入、恢复、状态流转）

## 12. 分期计划

| 期 | 范围 | 验收标准 |
|---|---|---|
| P1 | Tauri 壳、xterm.js 终端标签（真 zsh）、启动器式主页、侧边栏、点击恢复（含会话链）、新建对话（P1 阶段主页/侧边栏仅显示静态信息：标题与时间；实时状态色随 P2 到来） | 可作为日常终端使用并一键恢复任意历史对话 |
| P2 | 总览方块页（状态色/转圈/拖拽/重命名/排序）、实时刷新、hooks 一键安装、底部状态栏、上下文徽章 | 多对话状态一屏实时可见且准确 |
| P3 | 会话固定为浏览器式标签、右键菜单、多窗口、归档 | 窗口/标签自由度达到浏览器级 |
| P4 | sub-agent DAG 结构图（总览覆盖层 + 会话内面板） | 平行/顺序/混合结构可正确重建并实时更新 |
| P5 | 可编辑 pipeline：拖线编排、角色 prompt、记忆模式、输入映射、项目读取范围、角色模板库、自动执行与通知 | 示例流水线「写作→盲审→带记忆修订→逐段裁决→汇总」全自动跑通 |

每期交付均为完整可用状态。
