# aTerm V3.2a 实施计划：设置浮层 + macOS 菜单栏

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把侧栏底部的主题选择器与 hooks 安装器移进一个新的应用内设置浮层，并在
macOS 菜单栏加上「设置… ⌘,」与「主题模式」三项。

**Architecture:** 前端新增一个模态浮层组件 + 一个只管开关的 store；四个分区各自是
独立组件，读写既有的 theme / layout / library / hooksInstall 四个 store，不新增业务状态。
菜单在 Rust 侧扩展 `lib.rs` 已有的菜单代码，通过 `emit` 事件与一个自定义命令与前端双向同步。

**Tech Stack:** React 19 + TypeScript + zustand + vitest/RTL（无 jest-dom）；
Tauri 2.11.5（Rust 菜单 API）。

**Spec:** `docs/superpowers/specs/2026-09-01-aterm-v3-2a-design.md`

## Global Constraints

- **本仓库没有 jest-dom。** 只用 vitest 内置断言。禁止 `toBeInTheDocument`、
  `toHaveClass`、`toHaveValue`、`toHaveTextContent`。
- **所有颜色必须取自主题 CSS 变量**，禁止硬编码 hex / rgb / hsl / 颜色名
  （28 主题 × 3 模式）。可用变量见 `src/themes/derive.ts`。
- **受保护文件**：`src/components/ConversationPanel.tsx`、`src/components/TerminalView.tsx`。
  本计划不需要改它们；若认为必须改，停下来上报。
- **localStorage 键名一律不得变更**：`aterm.overview.names`、
  `aterm.library.hiddenProjects`、`aterm.library.removedSessions`、
  `aterm-wheel-multiplier`、主题相关键。别名 key 格式 `${dirName}::${rootKey}`（双冒号）
  同样不得变更。
- **aTerm 对 `~/.claude` 只读**，唯一例外是 hooks 安装器（用户明确点击时）。
- **测试绝不允许碰真实的 `~/.claude`**，一律用 tempfile 或 mock。
- 基线：`npx vitest run` 795 通过 / 57 文件；`cargo test` 115 通过；`npm run build` 干净。
- 每个任务结束时这三条都必须仍然成立（测试数只增不减）。

```ts
// src/store/settings.ts
import { create } from 'zustand'

// 只管设置浮层的开关。刻意不放进 store/layout.ts——那个文件已经承载面板宽度、
// 折叠状态、窗口尺寸联动、滚轮倍率等多项职责，继续堆积会让它更难读。
// 刻意不持久化：重启应用后设置浮层应当是关闭的。
type SettingsState = {
  open: boolean
  openSettings(): void
  closeSettings(): void
}

export const useSettings = create<SettingsState>((set) => ({
  open: false,
  openSettings: () => set({ open: true }),
  closeSettings: () => set({ open: false }),
}))
```

`derive.ts` 里按既有风格新增 `--color-scrim`：从主题的 `bg` 推导出一个半透明遮罩色。
**不要硬编码 `rgba(0,0,0,.5)`** —— 亮色主题下需要的是暗遮罩、暗色主题下同样需要暗遮罩
但透明度可以不同；具体推导方式参照该文件里既有变量的做法，并在代码里写一句注释说明
你选的推导规则。

- [ ] **Step 4: 实现容器**

要点（每一条都有对应的测试在盯）：
- `open === false` 时返回 `null`。
- 结构：`.settings-scrim`（遮罩，`onClick` 关闭）内含 `.settings-panel`
  （`role="dialog"`、`aria-modal="true"`、`aria-label="设置"`，`onClick` 里
  `e.stopPropagation()` 防止冒泡到遮罩）。
- `Esc`：在 `useEffect` 里监听 `window` 的 `keydown`，`open` 为 false 时不监听，
  卸载时移除。
- 焦点：打开时把焦点移进面板（`panelRef.current?.focus()`，面板加 `tabIndex={-1}`）；
  关闭时还给打开它的元素——用一个 ref 记住 `document.activeElement`，关闭时
  `previouslyFocused?.focus()`。
- 右上角关闭按钮：`aria-label="关闭设置"`。
- 面板内容区 `overflow-y: auto`，遮罩本身不滚动。
- 分区先留空占位，后续任务填。

样式全部用主题变量：遮罩 `background: var(--color-scrim)`；面板
`background: var(--color-panel)`、`border: 1px solid var(--color-border)`、
`color: var(--color-text)`。**不得出现任何硬编码颜色。**

  命令 `set_theme_mode_checked(mode: String)`。

- [ ] **Step 1: 写失败的测试**

Rust 侧：三个菜单项 id 与预期一致；`set_theme_mode_checked` 对合法模式恰好勾选一项，
对非法字符串返回 `Err` 且不改变任何勾选态。
（同样，若需真实句柄难以单测，把「模式字符串 → 三项各自的 checked 布尔」提成纯函数再测。）

前端侧：调用 `setMode` 之后，同步函数被调用且传的是新模式。

- [ ] **Step 2: 跑测试确认失败**

- [ ] **Step 3: 实现 Rust 侧**

- 新增顶层「主题」菜单，**追加到顶层末尾**（`menu.append`）。理由：
  `replace_quit_menu_item` 靠 `top_items.first()` 找 App 菜单，追加到末尾永远不会
  扰动这个假设；顶层菜单之间的先后只是观感问题，不值得为此引入下标计算。
- 三个 `CheckMenuItem`，标签与前端 `MODE_LABEL` 逐字一致：
  「默认」「双主题跟随系统」「手动选定」。id 分别为
  `aterm-theme-mode-default` / `-dual` / `-single`。
- `on_menu_event` 里加分支：命中时 `emit("menu-theme-mode", "<mode>")`。
- 新增命令：

```rust
#[tauri::command]
fn set_theme_mode_checked(app: AppHandle, mode: String) -> Result<(), String>
```

**必须显式设置全部三项**的 checked 状态（恰好一个 true），不能只设一项——
macOS 点击 `CheckMenuItem` 时系统会自行切换其勾选态，不重置其余两项就会出现多个勾选。
非法 mode 字符串返回 `Err`，且不改动任何一项。
记得加进 `generate_handler!`。

- [ ] **Step 4: 实现前端同步**

- 监听 `menu-theme-mode`，调 `useTheme.getState().setMode(payload)`。
  **payload 必须校验**是三个合法值之一，非法值忽略（不要直接透传给 `setMode`）。
- 应用启动、store 就绪后调用一次 `set_theme_mode_checked(mode)`；
  此后每次 `setMode` 之后再调用一次。
- 调用失败只 `console.warn`，**不要 `.catch(() => {})` 静默吞掉**——
